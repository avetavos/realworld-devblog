## How to use these

DevBlog สมบูรณ์ในแบบที่มันเป็น แต่โปรเจกต์จริงไม่เคยเสร็จ — มันเติบโตทันทีที่มีคนใช้งานจริง แบบฝึกหัดแปดข้อด้านล่างเรียงจากง่ายไปยากคร่าว ๆ และแต่ละข้ออุดช่องที่การสร้างจงใจเปิดไว้ หรือต่อยอดฟีเจอร์ที่คุณมีอยู่แล้ว เลือกทำตามลำดับหรือหยิบเฉพาะข้อที่สนใจ แต่ละข้อเป็นงานบ่ายเดียวที่จบในตัว ไม่ใช่การเขียนใหม่ทั้งหมด ทุกข้อมีคำแนะนำหนึ่งประโยคเพื่อชี้ไปยังเลเยอร์ที่ถูกต้อง — ที่เหลือเป็นของคุณที่จะออกแบบ

## The exercises

### 1 · Admin promotion / first-user-is-admin seed

อุดช่องที่ acceptance walk ทำด้วยมือ: เพิ่ม mutation `promoteToAdmin` ที่มี guard (เรียกได้เฉพาะ admin ที่มีอยู่แล้ว) หรือ seed ที่ทำให้ผู้ใช้คนแรกที่ลงทะเบียนเป็น admin โดยอัตโนมัติ เพื่อให้มีวิธีสร้างผู้ดูแลคนแรกในแอปที่ตรวจสอบย้อนหลังได้ แทนที่จะแก้ Mongo โดยตรง

### 2 · Full-text search over posts

เพิ่ม GraphQL query `searchPosts(query)` ที่หนุนหลังด้วย **text index** ของ MongoDB บนหัวข้อและเนื้อหาโพสต์ คืนเฉพาะโพสต์ที่เผยแพร่แล้วเรียงตามความเกี่ยวข้อง เพื่อให้ผู้อ่านค้นหาเนื้อหาได้โดยไม่ต้องรู้ slug ที่แน่นอน

### 3 · Cursor-based pagination

แทนที่ (หรือเพิ่มควบคู่กับ) offset pagination เดิมด้วย pagination แบบ **cursor** บน query โพสต์ — เข้ารหัส cursor จาก sort key ที่เสถียรอย่าง `publishedAt` บวก `_id` — เพื่อให้หน้ายังถูกต้องแม้มีโพสต์ใหม่ถูกเผยแพร่ระหว่างการร้องขอ

### 4 · Image uploads for cover images

ให้ผู้เขียนแนบภาพปกให้โพสต์ได้โดยรับ upload ใน admin dashboard เก็บไฟล์ (ดิสก์เครื่องสำหรับ development, bucket ที่เข้ากันได้กับ S3 สำหรับ production) และเก็บเพียง URL ของมันบน document โพสต์ แล้วเรนเดอร์บนหน้าโพสต์สาธารณะและใน SEO metadata

### 5 · Related posts by shared tags

เพิ่ม resolver `relatedPosts(slug)` ที่คืนโพสต์ที่เผยแพร่แล้วอื่น ๆ ซึ่งมีแท็กร่วมกับโพสต์ปัจจุบันมากที่สุด เพื่อให้หน้าโพสต์สาธารณะแสดงรายการ "คุณอาจชอบสิ่งเหล่านี้" ได้โดยไม่ต้องคัดเลือกด้วยมือ

### 6 · DataLoader to fix the `author` N+1

นำ **DataLoader** ที่มี scope ต่อ request สำหรับผู้ใช้เข้ามา และใช้มันภายใน resolver `@ResolveField author` เพื่อให้การเรนเดอร์รายการโพสต์ N รายการยิงการค้นหาผู้ใช้แบบ batch ครั้งเดียวแทนที่จะเป็น N query แยกกัน — การแก้ N+1 คลาสสิกของ GraphQL

### 7 · Rate-limit `addComment` and add a spam honeypot

ป้องกัน endpoint คอมเมนต์แบบไม่ระบุตัวตนด้วย rate limit ต่อ IP (`ThrottlerGuard` ของ NestJS) และฟิลด์ **honeypot** ที่ซ่อนไว้ซึ่งผู้ใช้จริงไม่มีวันกรอก โดยทิ้งการส่งใด ๆ ที่กรอกมันมา เพื่อไม่ให้คิวตรวจสอบจมด้วยบอต

### 8 · End-to-end tests with Playwright

เขียนชุดเทสต์ **Playwright** ที่โมดูล testing เพียงร่างไว้: ขับเบราว์เซอร์จริงผ่าน flow เต็ม publish→read→comment→moderate กับสแตก Docker Compose ที่กำลังรันอยู่ โดย assert การเปลี่ยนสถานะแต่ละอย่างที่ acceptance walk อธิบายไว้

## Recap

แบบฝึกหัดแปดข้อนี้ครอบคลุมทั้งสแตกที่คุณสร้าง — auth และการ seed, การทำ index และ pagination ของ MongoDB, การเก็บไฟล์, ประสิทธิภาพ GraphQL, การป้องกันการใช้งานในทางที่ผิด และการเทสต์แบบ end-to-end — และหลายข้ออุดช่องที่คอร์สพูดออกมาตรง ๆ แทนที่จะซ่อนไว้ อย่างการโปรโมต admin ที่ขาดหายและ `author` N+1 ทำสักสองสามข้อแล้ว DevBlog จะหยุดเป็นผลลัพธ์ของทิวทอเรียลและเริ่มเป็นโปรเจกต์*ของคุณ*
